    GETTING STARTED
SNIPER-$VVV DOCUMENTATION
SNIPER-$VVV is a tactical AI workspace that routes prompts through the configured OpenRouter provider. Available models and response quality depend on provider availability, account limits, and current routing.

    
Start a conversation
  1. Enter a question or task in the terminal input.
  2. Choose a workspace from the sidebar: General intelligence, Coding assistant, or Visual assistant.
  3. Select a suggested prompt or write your own, then choose EXECUTE.
  4. Review generated output before using it in production.

    
Workspace tools
  • Prompt tools: enhance prompts and summarize the current conversation.
  • Developer tools: review, explain, debug, refactor, document, and test code.
  • Project tools: organize sessions and add local reference files for project-aware assistance.
  • Engineering tools: inspect dependencies, review patches, run local heuristic checks, and prepare code plans.
  • Memory and snippets: optional browser-local preferences and reusable code snippets.

    
Commands
/help/clear/models/history/prompts/export

    
Important limitations
AI output can be incomplete or incorrect. Local project files and drafts remain in this browser unless a feature explicitly sends selected context with a prompt. The workspace does not automatically commit changes to GitHub or deploy your project.

This page describes the intended data handling visible from the current application interface. The project owner should verify it against hosting, server, analytics, and provider configurations before publication.

    INTEGRATION OVERVIEW
API REFERENCE
SNIPER-$VVV currently exposes an in-product AI interface. A public, stable developer API is not documented in this release.

    
Request flow
  1. The browser collects the message and any selected context.
  2. The application sends the request to its configured server-side endpoint.
  3. The server uses its configured OpenRouter credential to request a model response.
  4. The response is returned to the terminal for display.

    
Authentication and credentials
Do not place OpenRouter API keys in browser code, public repositories, or client-side environment variables. Configure secrets in the deployment environment and access them only from server-side code.

    
Availability and limits
Model availability, rate limits, and response formats depend on the configured provider and model. The current interface indicates verified automatic routing; it does not promise a fixed model or public API compatibility.

    
Endpoint paths, schemas, authentication headers, quotas, and versioning are intentionally not listed because a supported public API contract has not been established.

    HELP CENTER
FAQ & SUPPORT

    
Why can a model fail?
Provider availability, free-tier limits, rate limits, or temporary upstream errors can interrupt a request. Automatic routing may select another available route.

    
Are project files uploaded automatically?
Files added to the local project library are stored in this browser. They may be included when you explicitly run a project-aware feature or send selected context to AI. Avoid storing secrets.

    
Does AI directly change my GitHub repository?
No. Code plans and local workspace drafts require your review. Export or manually apply approved changes through your development workflow.

    
Can I rely on generated code or security reports?
No output is guaranteed. Review changes, run tests, inspect dependencies, and verify security findings independently.

    
Where can I report a problem?
Use the project's official repository issue tracker or support channel if the operator has enabled one.
